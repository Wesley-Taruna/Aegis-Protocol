## Note on reproducibility

These numbers were generated fresh in this session, not pulled from a prior saved file — no `results.json` existed anywhere in the `Aegis Protocol` folder before this run (the CLI only writes one when you pass `--output`). Because `wrong-key`/legitimate keys and the 5% fault injection use real randomness (`crypto.randomBytes`, `Math.random`), a re-run will land close to but not identical to the paper's published Table I (e.g. this run's mixed-fault success rate is 95% / 950 unique keys vs. the paper's 95.1% / 951). That's expected statistical variance, not an error — but it means "the test log" isn't a single fixed artifact; it's regenerated per run. If you want a canonical log to cite and archive permanently, this run's four JSON files can serve as that canonical version going forward.
